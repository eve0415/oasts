Everything oasts emits is derived from one model of your document, so the artifacts cannot disagree
about your API. Turn them on individually:

```yaml title="oasts.yaml"
artifacts:
  types: true
  client: true
  zod: false
  validators: false
  tanstack: false
  msw: false
validation:
  engine: "off"
  unchecked: allow
```

The client artifact requires an explicit `validation` block; `engine: "off"` opts out of boundary
checking. See [Validation](/artifacts/validation) for the other engines.

<Aside type="note">
  This build always emits the types artifact. `types: false` is accepted by the config and then
  ignored, so the `types/` directory is written either way.
</Aside>

Each artifact writes into its own directory under `output`, named after the artifact. Rename or nest
any of them with `artifacts.<name>.directory` and the imports between them follow — see
[Configuration](/reference/configuration#artifacts).
