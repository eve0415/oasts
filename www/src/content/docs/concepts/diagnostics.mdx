Every message oasts prints carries a stable code, a severity, and a pointer into the thing it is
talking about:

```text
error[OASTS0262]: filters.paths.include pattern '/^\/pets/' matches no operation; a regex pattern
must match the whole subject, so add `.*` to match a prefix or a substring
  --> ./oasts.yaml:1:1 /filters/paths/include/0
```

```text
warning[OASTS1406]: response key '200' is statically bodyless but declares media 'text/event-stream'
  --> ./openapi.yaml:1:1 /paths/~1probe/head/responses/200/content/text~1event-stream
```

The pointer's trailing path is a **JSON Pointer** into the document or config file — the exact node
the diagnostic is about, with `/` in a key escaped as `~1`.

## Severity

- **`error`** — nothing is written. The build fails.
- **`warning`** — generation continues, and the warning names what was skipped or adjusted. A
  warning always means one operation, one component, or one artifact projection did *not* come out
  the way an unqualified reading of the document would suggest.

Warnings matter more here than in most tools, because oasts never resolves an ambiguity silently.
If an operation vanished from an artifact, a warning says so and names it.

## Code families

The **thousands** digit is the stage that refused, and every code in a stage shares an exit code:

| Stage | What refused | Exit | For example |
| --- | --- | --- | --- |
| `0xxx` | **Config validation.** The file parsed, but something in it is not a usable instruction. | `2` | `OASTS0101` no artifact is enabled · `OASTS0111` the client artifact needs types on · `OASTS0262` a filter pattern matches nothing |
| `1xxx` | **I/O.** A file oasts had to read or write did not cooperate. | `2` | `OASTS1001` the config could not be read · `OASTS1002` your tsconfig is unreadable or is not valid JSONC · `OASTS1013` writing an output file failed |
| `2xxx` | **Document loading and structure.** The document, its `$ref` graph, or a schema keyword. | `1` | `OASTS2003` the document is not valid YAML or JSON · `OASTS2013` the `limits.maxDocuments` bound was exceeded · `OASTS2201` a construct this OpenAPI version does not define |
| `3xxx` | **Semantics.** Names, value domains, links. | `1` | `OASTS3001` two operations want the same identifier · `OASTS3002` two schemas want the same type name · `OASTS3201` a Link Object's `operationId` names no operation |
| `4xxx` | **Type emission.** Turning the model into TypeScript. | `1` | `OASTS4105` a compiler-invented name has nowhere left to move · `OASTS4201` an `allOf` proven empty, lowered to `never` |
| `5xxx` | **Client model.** Projecting operations into the request and response pipeline. | `1` | `OASTS5201` an XML response media · `OASTS5403` an OAuth2 scheme declaring no flows |
| `6xxx` | **Artifacts.** One sub-band per artifact. | `1` | `OASTS6002` validators cannot check a keyword · `OASTS6201` a path literal MSW's matcher cannot match |
| `9xxx` | **Provisional.** A capability this build gates off rather than refuses. | varies | `OASTS9003` a reserved config block · `OASTS9101` a remote `$ref` |

The **hundreds** digit sub-divides a stage: `62xx` is MSW's corner of the artifact stage, `22xx` is
the schema-keyword corner of document loading. Sub-bands are kept sparse deliberately, so a new code
joins its siblings instead of landing at the end of a run.

The exit code is a property of each diagnostic, not something parsed back out of its number. Every
code carries a category, and stages are drawn so that all the codes in one share it — that is what
makes the `Exit` column true rather than coincidental. A code whose category disagrees with its
stage is a bug. See [exit codes](/reference/cli) for what `1` and `2` mean at the shell.

`0xxx` has a finer address: `0rrs`, where `rr` is a config rule and `s` is a sequence within it.
`OASTS0262` is rule 26 — filters — sequence 2. Codes sharing an `rr` are different ways of failing
the same rule, so `0261`, `0262` and `0263` are all about filters, widening from one pattern to one
axis to the whole block.

### The provisional band

`9xxx` is not a stage. It holds capabilities this build gates off rather than refuses on the merits
— `OASTS9101` for a remote `$ref`, `OASTS9003` for a config block that is accepted by the schema but
not implemented. A provisional code **retires when its capability lands**, so the band is expected to
develop holes, and nothing is renumbered to close them.

The second digit tells you which stage the code would otherwise have sat in. Treat it as a hint
about where the refusal came from, not as a way to work out the exit code — read that off the
category the diagnostic carries. `99xx` is reserved for test sentinels and is never emitted.

## Refusals you are most likely to meet

### Configuration

| Code | Meaning |
| --- | --- |
| `OASTS0102` | Two enabled artifacts share a directory, or one nests inside another |
| `OASTS0261` | A filter pattern is a regex literal whose body does not compile |
| `OASTS0262` | A filter pattern matches no operation in the document |
| `OASTS0263` | Filters selected operations but left none of them, and no webhooks either |

### Document and schema

| Code | Meaning |
| --- | --- |
| `OASTS1115` | A discriminator `mapping` value that is not a JSON string, so it cannot name a schema |
| `OASTS1117` | A `$recursiveRef` written with a value other than `"#"` |
| `OASTS1118` | A dynamic reference whose target genuinely depends on the path evaluation took to reach it |
| `OASTS1119` | Pruning removed every component schema and there was nothing else to emit |
| `OASTS1120` | A lowercase status range (`4xx`) — canonicalized and reported, not rejected |
| `OASTS1121` | Two keys in one responses object naming the same status once canonicalized |
| `OASTS1122` | A narrowing keyword the emitted TypeScript cannot apply, where the leaf does *not* widen to `unknown` |

### Names the compiler will not invent

These are the [naming](/guides/naming) refusals. Each has a remedy in `naming.overrides`.

| Code | Meaning |
| --- | --- |
| `OASTS1307` | A renamed component import collides with another operation-module rename |
| `OASTS1308` | A discriminator `mapping` value resolving to no allocated component schema |
| `OASTS1309` | A discriminator whose `mapping`/`const` proof is internally incoherent |
| `OASTS1310` | A request/response variant's replacement name is itself declared, or another variant's replacement |
| `OASTS1311` | A wire twin's derived `{Name}Wire` is already a declared component's name |
| `OASTS1312` | `{Name}WireValue` is itself declared — nothing compiler-invented remains, so the document is refused |
| `OASTS1313` | A union whose branches convert date/time values differently, with nothing to tell them apart |
| `OASTS1315` | A property two `allOf` branches declare with schemas that intersect to nothing (warning) |
| `OASTS1316` | A discriminator that can select branches, but whose union lacks unit-literal tags on every branch |
| `OASTS1400` | A JSON response media entry renamed because its validator-name fragment collided |

### Artifact projections

An artifact that cannot express one thing skips that thing and warns; the rest still generates.

| Code | Artifact | Meaning |
| --- | --- | --- |
| `OASTS1501` | validators | A validation keyword the validators artifact does not implement |
| `OASTS1502` | validators | A schema degraded to an unknown leaf, so no faithful validator exists |
| `OASTS1503` | validators | An applicator's subschema is not fully checkable, so the outer check would be unsound |
| `OASTS1504` | zod | A validation keyword the Zod artifact does not implement |
| `OASTS1505` | zod | A schema degraded to an unknown leaf, so no faithful Zod schema exists |
| `OASTS1506` | msw | A path literal carrying a character the MSW matcher cannot match |
| `OASTS1507` | msw | An HTTP method for which MSW exposes no handler factory |
| `OASTS1508` | msw | A parameter's wire form cannot be inverted into its TypeScript type |
| `OASTS1509` | msw | A body cannot be projected between wire form and TypeScript type |
| `OASTS1510` | msw | A parameter serialization loses boundaries before the handler can project it |
| `OASTS1511` | tanstack | A read carries no payload on at least one success branch, so it emits no query descriptor |
| `OASTS1512` | tanstack | Two path nodes normalize to the same key-factory name |
| `OASTS1513` | tanstack | A `naming.overrides.pathSegments` entry matched no path segment |
| `OASTS1514` | msw | A streaming body has no buffered value to project in either direction |
| `OASTS1515` | msw | A form body whose schema declares no properties — the handler is emitted with no body fields |

<Aside type="note">
  This is the set you are most likely to hit, not the complete allocation. Run
  [`oasts check`](/reference/cli) to see every diagnostic your own document and config produce,
  without writing any files.
</Aside>
