Given the same input document *bytes*, the same config, the same oasts version, and the same
consumer `tsconfig.json`, output is **byte-identical** across machines and operating systems. That
is a contract, not an aspiration — the repo's own gates generate 39 fixture configurations twice
and diff the bytes.

Two things in that sentence are load-bearing. Your `tsconfig.json` is the only consumer-side file
that reaches emitted bytes: it decides whether generated code carries the `esnext.temporal`
reference directive, and `typescript.tsconfig: off` drops that dependency. And identity is keyed to
your document's bytes, not its meaning — reformatting your OpenAPI file with no semantic change
shifts the recorded source digest and will drift `--check`.

## Commit the output

Generated code is a build artifact you can review in a pull request. When output is stable, a diff
means something changed in your API, and reviewers can read it. Nothing regenerates behind you at
install time, and nothing depends on a generator being present at build time.

## Gate the output

In CI, fail on drift instead of writing files:

```sh
pnpm exec oasts generate --check
```

`--check` compares what would be written against **what is on disk** and exits non-zero on any
difference. It reads a `.oasts-manifest.json` sidecar in the output directory, so commit that file
along with the generated code — without it, `--check` cannot spot a stale leftover.

Pair it with `oasts check`, which validates your configuration and input document without emitting
anything:

```sh
pnpm exec oasts check
```

```yaml title=".github/workflows/ci.yaml"
- run: pnpm install --frozen-lockfile
- run: pnpm exec oasts generate --check
```

## What the header records

Every emitted file opens with `// Generated by Oasts <version>. Do not edit.`, the config schema
version, and a `Source digest` over your document's raw bytes. There is no timestamp. Two
consequences for review: upgrading oasts touches the first line of every file, and the digest line
is where a reformatted document shows up.

## No formatter, ever

Emitted code has one canonical shape. oasts never reformats your project, and you should never run
a formatter over its output — doing so guarantees a diff on the next `--check`.

<Aside type="tip">
  If your formatter runs over the whole repo, add the output directory to its ignore file. The
  point of byte-identical output is that a diff carries information; a formatter pass destroys
  that.
</Aside>
